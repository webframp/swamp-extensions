# @webframp/datadog/dora

Datadog DORA Metrics — deployment frequency, lead time, MTTR, and change failure
rate

Auto-generated by `scripts/datadog-codegen` from the Datadog v2 REST API OpenAPI
specification.

## Credentials

Datadog authenticates with two keys: an API key and an application key. Store
both in a swamp vault and reference them with `vault.get` expressions; never
pass the literal values. Any vault type works — `local_encryption`, or an
extension such as `@webframp/pass`, `@webframp/gopass`,
`@webframp/hashicorp-vault` or `@webframp/macos-keychain`.

```bash
swamp vault create local_encryption datadog   # once, if you have no vault yet
swamp vault put datadog API_KEY               # prompts; the value never touches shell history
swamp vault put datadog APP_KEY
```

## Usage

```bash
swamp extension pull @webframp/datadog/dora

swamp model create @webframp/datadog/dora dd-dora \
  --global-arg 'apiKey=${{ vault.get("datadog", "API_KEY") }}' \
  --global-arg 'appKey=${{ vault.get("datadog", "APP_KEY") }}' \
  --global-arg site=us1
```

## Methods

| Method                             | Description                            |
| ---------------------------------- | -------------------------------------- |
| `create_dora_deployment`           | Send a deployment event                |
| `delete_dora_deployment`           | Delete a deployment event              |
| `list_dora_deployments`            | Get a list of deployment events        |
| `patch_dora_deployment_by_version` | Mark a deployment as failed by version |
| `get_dora_deployment`              | Get a deployment event                 |
| `patch_dora_deployment`            | Mark a deployment as failed by ID      |
| `create_dora_failure`              | Send an incident event                 |
| `delete_dora_failure`              | Delete an incident event               |
| `list_dora_failures`               | Get a list of incident events          |
| `get_dora_failure`                 | Get an incident event                  |
