# @webframp/datadog/synthetics

Datadog Synthetics — synthetic monitoring tests, results, and locations

Auto-generated by `scripts/datadog-codegen` from the Datadog v2 REST API OpenAPI
specification.

## Credentials

Datadog authenticates with two keys: an API key and an application key. Store
both in a swamp vault and reference them with `vault.get` expressions; never
pass the literal values. Any vault type works — `local_encryption`, or an
extension such as `@webframp/pass`, `@webframp/gopass`,
`@webframp/hashicorp-vault` or `@webframp/macos-keychain`.

```bash
swamp vault create local_encryption datadog   # once, if you have no vault yet
swamp vault put datadog API_KEY               # prompts; the value never touches shell history
swamp vault put datadog APP_KEY
```

## Usage

```bash
swamp extension pull @webframp/datadog/synthetics

swamp model create @webframp/datadog/synthetics dd-synthetics \
  --global-arg 'apiKey=${{ vault.get("datadog", "API_KEY") }}' \
  --global-arg 'appKey=${{ vault.get("datadog", "APP_KEY") }}' \
  --global-arg site=us1
```

## Secrets

These methods receive secrets from Datadog. swamp stores each listed field in a
vault and the stored resource keeps only a `vault.get` reference. Because the
model declares sensitive output, swamp refuses to run any of its methods, reads
included, until a vault exists (`swamp vault create local_encryption datadog`).

| Method                                   | Fields stored in a vault          |
| ---------------------------------------- | --------------------------------- |
| `get_test_file_download_url`             | `url`                             |
| `get_test_file_multipart_presigned_urls` | `multipart_presigned_urls_params` |
| `patch_global_variable`                  | `value.value`                     |
