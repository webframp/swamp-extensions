# @webframp/dnsimple/certificates

DNSimple Certificates — certificates, Let's Encrypt orders and renewals, and
private keys

Auto-generated by `scripts/dnsimple-codegen` from DNSimple's API v2 OpenAPI
specification.

## Usage

```bash
swamp extension pull @webframp/dnsimple/certificates
```

## Credentials

Store the DNSimple access token in a swamp vault and reference it with a
`vault.get` expression; never pass the literal value. Any vault type works —
`local_encryption`, or an extension such as `@webframp/pass`,
`@webframp/gopass`, `@webframp/hashicorp-vault` or `@webframp/macos-keychain`.

```bash
swamp vault create local_encryption dnsimple   # once, if you have no vault yet
swamp vault put dnsimple ACCESS_TOKEN             # prompts; the value never reaches shell history
swamp model create @webframp/dnsimple/certificates dnsimple-certificates \
  --global-arg 'apiToken=${{ vault.get("dnsimple", "ACCESS_TOKEN") }}' \
  --global-arg accountId=<account id from whoami>
```

If `apiToken` is unset, the model reads the `DNSIMPLE_TOKEN` environment
variable as a fallback. That value is not redacted from swamp output and is not
recommended.

## Account and environment

Account-scoped methods substitute the `accountId` global argument for the
`/{account}` path segment. It stays optional so `whoami` and `list_accounts` (in
`@webframp/dnsimple/account`) can run before you know the ID; an account-scoped
method without it fails before any request goes out.

`environment` is `production` by default. Set `--global-arg environment=sandbox`
to use DNSimple's sandbox, which has its own accounts and tokens.

## Billable methods

These methods charge the DNSimple account. Their descriptions open with
"Billable:". Try them against the sandbox first.

- `purchase_letsencrypt_certificate`
- `purchase_renewal_letsencrypt_certificate`

Some methods return secrets, which swamp stores in a vault (see
[Secrets](#secrets)). Because the model declares these fields sensitive, swamp
refuses to run any of its methods, reads included, until a vault exists
(`swamp vault create local_encryption dnsimple`).

## Secrets

These methods return a secret. The resource marks each listed field sensitive,
so swamp stores the value in a vault and the resource keeps only a
`vault.get(...)` reference. Because the model declares these fields sensitive,
swamp refuses to run any of its methods, reads included, until a vault exists
(`swamp vault create local_encryption dnsimple`). The stored reference names the
vault and key that hold the secret; use that `vault.get(...)` expression
wherever another model needs it.

| Method                        | Fields stored in a vault |
| ----------------------------- | ------------------------ |
| `get_certificate_private_key` | `private_key`            |

## Methods

| Method                                     | Description                                          |
| ------------------------------------------ | ---------------------------------------------------- |
| `list_certificates`                        | List certificates                                    |
| `get_certificate`                          | Retrieve a certificate                               |
| `download_certificate`                     | Download a certificate                               |
| `get_certificate_private_key`              | Retrieve a certificate private key                   |
| `purchase_letsencrypt_certificate`         | Billable: Let's Encrypt: Order a certificate         |
| `issue_letsencrypt_certificate`            | Let's Encrypt: Issue a certificate                   |
| `purchase_renewal_letsencrypt_certificate` | Billable: Let's Encrypt: Order a certificate renewal |
| `issue_renewal_letsencrypt_certificate`    | Let's Encrypt: Issue a certificate renewal           |
