# @webframp/griptape/data-connectors

Griptape Cloud Data Connectors — data source connectors and ingest jobs

Auto-generated by `scripts/griptape-codegen` from the Griptape Cloud OpenAPI
specification.

## Credentials

Store the Griptape Cloud API key in a swamp vault and reference it with a
`vault.get` expression; never pass the literal value. Any vault type works —
`local_encryption`, or an extension such as `@webframp/pass`,
`@webframp/gopass`, `@webframp/hashicorp-vault` or `@webframp/macos-keychain`.

```bash
swamp extension pull @webframp/griptape/data-connectors

swamp vault create local_encryption griptape   # once, if you have no vault yet
swamp vault put griptape API_KEY               # prompts; the value never touches shell history
swamp model create @webframp/griptape/data-connectors gt-data-connectors \
  --global-arg 'apiKey=${{ vault.get("griptape", "API_KEY") }}'
```

The `GT_CLOUD_API_KEY` environment variable is read as a fallback when `apiKey`
is unset, but it is not redacted and is not recommended. An optional `baseUrl`
argument overrides `GT_CLOUD_BASE_URL` and the built-in default
(`https://cloud.griptape.ai`).

Some responses carry a credential, which swamp stores in a vault (see
[Secrets](#secrets)). Because the model declares sensitive fields, swamp refuses
to run any of its methods, reads included, until a vault exists
(`swamp vault create local_encryption griptape`).

## Secrets

### Secret-valued arguments

These method arguments carry a credential:

- `create_data_connector`: `config`
- `update_data_connector`: `config`

Method inputs are recorded with the run. Pass a credential as a `vault.get`
expression so the recorded input holds the reference, not the secret; a literal
value is recorded in cleartext.

`config` is an object that holds the credential in one of its fields. Put the
`vault.get` expression on that field, not the literal value.

### Credentials in responses

Some responses carry a credential:

- The `data_connector` resource marks `config.google_drive.access_token` as
  sensitive. Swamp stores the value in a vault and the resource holds a vault
  reference.
- `list_data_connectors` drops `config.google_drive.access_token` from every
  item before writing the snapshot. Swamp cannot vault a field inside a list, so
  use the matching get method to keep the value.

Because the model declares sensitive fields, swamp refuses to run any of its
methods, reads included, until a vault exists
(`swamp vault create local_encryption griptape`).
