### [LOW] `from`/`to` are unvalidated free strings and now go into the data name
**File:** redmine.ts **Line(s):** 1840-1841, 1906-1907
**Issue:** The schema says `YYYY-MM-DD` but accepts any string. Redmine's `parse_date` silently ignores a date it cannot parse, so the run fetches unfiltered entries and then:
- with `from: "01/01/2026"`, the write fails on swamp's path-traversal check, with a confusing message;
- with `from: "2026-01-01-to:2026-02-01"` and no `to`, it gets the same name as the properly filtered `{from:"2026-01-01", to:"2026-02-01"}` and overwrites it with unfiltered data.

**Impact:** Only user error can trigger it, but the CLAUDE.md rule "Zod schemas are the contract" applies.
**Fix:** `z.string().regex(/^\d{4}-\d{2}-\d{2}$/)` on `from` and `to`.
