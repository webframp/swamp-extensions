### [MEDIUM] Guard scans zero files and still passes when the root path has a dot-directory ancestor
**File:** scripts/check-reserved-names/main.ts  **Line(s):** 15-18, 26-31
**Issue:** The `SKIP_DIRS` regex `/(^|\/)\.[^/]+(\/|$)/` is matched against the absolute entry path, not the path relative to the root. If any ancestor of the scan root starts with a dot, every file is skipped, and the scan still exits 0.
**Breaking input:** `deno task --cwd scripts/check-reserved-names scan /tmp/.hid/x`, with a file containing `writeResource("a","latest",d)` underneath, prints `scanned 0 files, 0 finding(s)`. The same file under a non-dot path is flagged.
**Impact:** On GitHub Actions the workspace is `/home/runner/work/...`, so CI works today. The guard fails open on a self-hosted runner, a local run under `~/.cache` or `~/.worktrees`, or any root with a dotted parent.
**Fix:** Pass `walk` a skip regex tested against the relative path, or compute the relative path first. Also exit non-zero when `scanned` is 0 or below a floor.

### [MEDIUM] Guard cannot see indirect reserved names
**File:** scripts/check-reserved-names/lib/scan.ts  **Line(s):** 29-47
**Issue:** The regex only matches a quoted literal as the direct data-name argument. I confirmed it misses all of these, each passed as the data name:
- `const n = "latest"; writeResource("a", n, d)`

**Fix:** Either say in the header comment that the guard is literal-only, or extend it to flag any quoted `latest` literal in a `writeResource` or `readResource` statement. Case-folding would also help.
