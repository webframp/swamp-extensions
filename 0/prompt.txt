Fix the swamp-adoption scaffold so extensions it generates earn the registry's license points.

Context: swamp 20261014.121640.0 (swamp-club#3324, commit 8dd0e86e in ~/src/swamp-club/swamp)
split the quality rubric's license check in two. `has-license` now needs a valid SPDX
`license:` in manifest.yaml. `license-file` needs a non-empty LICENSE/LICENSE.md in the
archive, listed as a bare basename under `additionalFiles:`. PR #491 in
webframp/swamp-extensions added `license: Apache-2.0` to every manifest in the repo and to
the five scripts/*-codegen generators. The swamp-adoption scaffold was deliberately left out
because it is published for other users, so hard-coding Apache-2.0 is wrong.

Today the scaffold (swamp-adoption/extensions/models/swamp-adoption/mod.ts, near the
`manifestVersion: 1` array around line 730) emits a manifest with no `license:` and, check
whether it emits a LICENSE file at all. Scaffolded extensions therefore score 92% (or lower)
and fail `swamp extension quality`.
