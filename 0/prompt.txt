### [MEDIUM] README use-package recipe breaks init under `straight-use-package-by-default`
**File:** README.md **Line(s):** use-package + straight.el block
**Issue:** `(use-package swamp-present :after swamp)` has no `:straight nil` (or `:ensure nil`). With `straight-use-package-by-default t`, which is the usual setup for readers of this section, straight tries to install a package called `swamp-present` from its recipe repositories and fails. **Breaking input:** the snippet copied verbatim. **Impact:** an init error. **Fix:** `(use-package swamp-present :straight nil :after swamp)`.

### [MEDIUM] `swamp-present-pdf` always rebuilds the CDN deck, overwriting a self-contained build
**File:** swamp-present.el **Line(s):** 259-263
**Issue:** The PDF command hard-codes `self-contained` to nil and takes no prefix argument, unlike build and preview. If the stored deck was self-contained, the PDF build replaces it with a CDN version, and Chromium then has to fetch reveal.js from jsDelivr. **Breaking input:** `C-u M-x swamp-present-build` offline, then `M-x swamp-present-pdf`. **Impact:**
- Offline PDF export fails or hits the 120 s timeout, which defeats the stated purpose of self-contained decks.
- The stored latest deck silently stops being self-contained.

**Fix:** add `(interactive "P")` and pass it through, matching the other two commands, or reuse the existing build when it is self-contained.

### [MEDIUM] A second PDF export prompts "File changed on disk. Reread from disk?"
**File:** swamp-present.el **Line(s):** 276-283
**Issue:** The PDF is rewritten to the same path every time, then opened with `find-file-other-window`. If an earlier PDF buffer is still open, `find-file` asks the user to reread it (confirmed in batch: `"File x.txt changed on disk.  Reread from disk? "`). This happens even when the PDF is unchanged, because the rewrite updates the file's modification time. The prompt comes from inside a process sentinel. **Impact:** answering "no" shows a stale PDF while the echo area reports the new page count. **Fix:** revert an existing buffer visiting the file (`find-buffer-visiting` plus `revert-buffer t t`) before displaying it.

### [LOW] "Model not found" errors show only a generic message
**File:** swamp-present.el **Line(s):** 155-164
**Issue:** swamp writes `{"error":"Model not found: nope","code":"model_not_found"}` to stderr, not stdout; checked with the real CLI. `--run` only parses stdout, so the echo area shows "build failed (exit 1); see *swamp-present*". This hits exactly the most common setup mistake. **Fix:** when stdout does not parse, also try parsing stderr for `error`.

### [LOW] An untrusted file can choose which model instance's `build` method runs
**File:** swamp-present.el **Line(s):** 51-56, 79-90
**Issue:** `#+SWAMP_DECK:` is read without validation, and `swamp-present-deck` is `:safe #'stringp`, so a file-local variable can set it without a prompt. Either way, an untrusted Org or Markdown file can name any model instance in the configured repo, and `build --input source=&lt;file&gt;` then runs on it. A leading `-` is also accepted (`--help` and `--repo-dir=/x` get passed as options). This is not exploitable beyond picking a different `build` method, and the user must invoke the command. **Fix:**
- Validate the name against a strict pattern that rejects a leading `-`.
- Narrow the `:safe` predicate the same way.
- Optionally check that the instance's type is `@webframp/presentation/deck`.

### [LOW] `safe-local-variable` predicate is looser than swamp's `DECK_NAME_PATTERN`
**File:** swamp-present.el **Line(s):** 69-70
**Issue:** The extension's `_lib/source.ts` allows `^[a-z0-9][a-z0-9-]{0,62}$`. The Elisp predicate has no length cap, so a 64+ character name is accepted as safe and then rejected by swamp. **Fix:** use `\\`[a-z0-9][a-z0-9-]\\{0,62\\}\\'`.

### [LOW] Predictable output file names in a shared temporary directory
**File:** swamp-present.el **Line(s):** 188-200
**Issue:**
- `/tmp/swamp-present-&lt;name&gt;.html` and `.pdf` are written with `with-temp-file`, which follows symlinks. Linux `fs.protected_symlinks` mitigates this on most systems.
- Two deck instances whose sources share a name write to the same file.

**Fix:** default to a per-user directory (for example under `user-emacs-directory` or `$XDG_RUNTIME_DIR`), and include the deck instance in the file name.

### [LOW] No timeout or cancel, and `--fetch` blocks Emacs from inside a sentinel
**File:** swamp-present.el **Line(s):** 135-186
**Issue:** The async processes never time out, so a stuck swamp (for example, waiting on a model lock) runs until killed from `list-processes`. `swamp-present--fetch` is a synchronous `call-process` running inside the sentinel, and it freezes Emacs for as long as the query takes. **Fix:** add an optional timeout, or a cancel command that kills `swamp-present*` processes.
