### [MEDIUM] isDirectory fails open on any stat error other than "not found"
File: `/home/sme/src/webframp/swamp-extensions/.worktrees/feat-pass-first-line-fields/vault/pass/extensions/vaults/pass.ts`
Line(s): 315-327
Issue: both `catch` blocks catch every error. If the stat is refused rather than missing (for example a Deno `NotCapable`/`PermissionDenied` error), the second stat fails the same way and the function returns `false`. The tree listing then goes through `firstLine` and comes back as the password, which is the bug this commit fixes.
Breaking input: I confirmed this with real pass. The same store run with `--allow-read` returns `ERR pass key "smtp" is a directory`. Run without `--allow-read`, or with `--allow-read=/nonexistent`, it returns `get("smtp") =&gt; "swamp/smtp"` under `passwordOnly`. With a field selection it falls through to the "has no field" error instead of the directory error.
Impact: this only happens where the host process can run `pass` but can't read the store. Plain filesystem EACCES makes pass fail too, so the realistic trigger is a Deno permission sandbox. I did not check whether swamp grants read permission to extensions. Failing open hands back a wrong secret without any error.
Fix: count only `Deno.errors.NotFound` as missing and rethrow anything else. `NotFound` alone isn't enough, because an error thrown inside `withVaultSpan` still records only `error.type`.

### [LOW] `.gpg` check accepts any file type, but pass requires a regular file
File: same, line 317
Issue: pass tests `-f`, a regular file. `Deno.stat` succeeds for a directory, FIFO or socket named `&lt;entry&gt;.gpg`.
Breaking input: `swamp/odd.gpg/` and `swamp/odd/` both directories. pass prints the tree of `odd`, and `get("odd")` with `passwordOnly` returns `"swamp/odd"`. Confirmed empirically.
Impact: requires a store containing a directory ending in `.gpg`, which is very unlikely.
Fix: `return !(await Deno.stat(...)).isFile ? &lt;fall through&gt; : false`. In other words, treat it as an entry only when `.isFile` is true.
