## Harness fixes
- **Response schemas are lenient.**
  - Enums widen to their primitive type, value constraints drop, and properties accept null or absence.
  - Unknown fields pass through at every depth.
  - Request args stay strict.
  - When a list and a get/create method write the same resource, the schema is a union covering both.
- **Request hardening.**
  - Each attempt has a 30-second timeout, including the body read.
  - 429 handling no longer crashes with "Body already consumed". Retries clamp `Retry-After` to 30 seconds and then report the rate limit.
  - Empty 2xx bodies return `{}`.
  - Malformed JSON and HTTP errors name the status and request.
  - Pagination links must stay on the Snyk origin under `/rest`, so the token cannot leak to another host.
  - Get and create methods reject an empty body only where the spec promises content.
  - Array `data` on a non-list call is kept under `items`.
- **Query parameters.**
  - Dotted API names (`meta.latest_issue_counts`, `scan_item.id`) were being sent under mangled names. They are now sent correctly.
  - Array parameters accept a string or a list (the `provider` finding).
  - Create, update and action methods now send their declared query params. They were dropped before.
- **Resource names.** Every write method writes the resource the model declares. Six POST methods named `update_*` or `get_*` wrote to an undeclared name before: two in apps, one each in cloud and collections, and two in service-accounts.
- **Response `$ref` resolution.** `list_group_issues` and `list_org_issues` were misclassified as single-item reads and stored `{}`. They now page like lists. Their resources are renamed to `group_issues` and `org_issues`, with an Upgrade note in the issues release notes.
- **Generated tests.** Every method now runs an execute test asserting verb, exact path, query params and body, and validates the written data against the declared resource schema. Before, only a few methods were exercised.
- **Version detection.** It now also compares the shared API helper and the test file, so helper-only changes bump the version.
- **Descriptions** truncate at word boundaries, and the release notes were tightened.

## What was broken
- Response schemas rejected a whole page on one unexpected enum value, null, or missing field.
- Requests had no timeout, and 429 exhaustion crashed with "Body already consumed". An empty 2xx body or malformed JSON gave a bare parse error with no status or request.
- Pagination followed a next link to any origin and sent the API token with it.
- Query parameters with dotted names (meta.latest_issue_counts, scan_item.id) were sent under mangled names. Create and update methods dropped their declared query parameters. Array parameters could not take a list.
- Six POST methods named update_* or get_* wrote to a resource the model never declared (apps, cloud, collections, service-accounts).
- list_group_issues and list_org_issues were misclassified as single-item reads and stored an empty object. create_deployment_credential and list_assets stored an empty object because their data is a list.
- A resource written by both a list and a get or create method used one schema that rejected the other writer's data.
- Generated tests executed only a few methods, and a change to the shared helper or the tests did not bump the version.

## What changed
- Response schemas accept what the API returns. Request validation is unchanged except that array query parameters accept a string or a list.
- 30-second timeout per attempt, clamped 429 retries with a clear final error, empty 2xx bodies accepted, errors that name the status and request, and pagination restricted to the Snyk origin under /rest.
- get and create methods fail on an empty body only where the spec promises content, so 204 mutations still succeed.
- Resources written by several methods get a union schema. Shared list responses resolve through $ref.
- Every generated method now has an execute test asserting verb, exact path, query parameters, and body, and the written data is checked against the resource schema.
