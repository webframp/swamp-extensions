### [MEDIUM] cloudflare-audit documents an environment-variable fallback that does not exist
**File:** `cloudflare-audit/README.md` **Line(s):** 73-75; `cloudflare-audit/RELEASE_NOTES.md` 7-8
**Issue:** The README says the Cloudflare models read `CLOUDFLARE_API_TOKEN` when `apiToken` is unset. The audit workflow uses the hand-written `@webframp/cloudflare/{zone,dns,waf,worker,cache}` models in `cloudflare/extensions/models/cloudflare/`. Those have no `Deno.env` read at all, and `apiToken` is required (`z.string().min(1)`), so it can never be unset. Only the generated `cloudflare/*/_lib/api.ts` models have the fallback. The release note repeats the false claim.
**Breaking input:** Creating `cf-zone` without `apiToken` and exporting the variable fails schema validation.
**Impact:** The docs describe behaviour that does not exist.
**Fix:** Delete the paragraph and the release-note sentence.
