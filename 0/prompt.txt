### HIGH `update_issue` can no longer clear a milestone
**File:** `/home/sme/src/webframp/swamp-extensions/.worktrees/fix-gitlab-positive-int-ids/gitlab/extensions/models/gitlab/projects.ts`
**Line(s):** 2057-2067 (`milestoneArg`), 3979-3981 (`update_issue` arguments), 4022-4029 (the `milestone_id` body)
**Issue:** `update_issue` sends the milestone as a REST `PUT /issues/:iid` with `milestone_id`. GitLab's Edit-issue API says of that field: "Set to 0 or provide an empty value to unassign a milestone." On the old code, `milestone: 0` or `"0"` went through `resolveMilestoneId` unchanged and became `milestone_id: 0`, which unassigned the milestone. That was the only way to do it with this extension, since `update_issue` has no null or clear option. The new union rejects both 0 and every all-zero string, so the feature is gone with no replacement. The code comment ("rejected like the number 0") treats 0 as meaningless, which is wrong for this endpoint.

This was neither documented in the README nor tested, but it was real behavior on a documented GitLab endpoint. `create_issue` is different: it sends `gid://gitlab/Milestone/0` to GraphQL, which means nothing, so rejecting 0 there is correct.
**Breaking input:** `update_issue { project: "g/p", iid: 7, milestone: 0 }`. Before, the milestone was cleared. Now it fails validation, and there is no other way to clear it.
**Impact:** A capability is silently removed. The release notes say `"0"` "used to be sent as milestone ID 0" but not that this meant "unassign", so a user can't tell they lost anything. Under your no-deferral rule, removing scope like this needs your decision.
**Fix:** This needs your call. Options:
- (a) For `update_issue` only, accept 0 and `"0"` and describe them as "0 clears the milestone". Keep `create_issue` positive-only.
- (b) Add an explicit `milestone: null` (or `clearMilestone: true`) that sends `milestone_id: 0`, and keep 0 rejected.

Either option needs a test asserting that the PUT body carries `milestone_id: 0`, plus an accurate release note. I recommend (a): it keeps the old behavior and is the smallest change.
