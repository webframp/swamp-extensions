### [MEDIUM] Terraform masking can turn an object attribute into a string, and the drift report breaks on it
**File:** terraform/extensions/models/terraform/terraform.ts **Line(s):** 221-239 (`redactSensitiveValues`); consumer aws/terraform-drift/extensions/reports/drift_report.ts 476-497
**Issue:** When `sensitive_values` marks a whole map attribute `true`, the attribute becomes the string `"***SENSITIVE***"`. `compareTags` casts `tags_all ?? tags` to a record and runs `Object.entries(tfTags)` and `key in tfTags` on it.
**Breaking input:** `tags = merge(local.base, { Owner = var.owner })` with `variable "owner" { sensitive = true }`. `merge()` marks the whole result sensitive, so `sensitive_values.tags = true`. This hits a resource with no `tags_all`, or one whose `tags_all` is also marked.
**Impact:** `Object.entries` on the string yields 15 per-character "drifts" (`tags.0: "*"`), and `key in "&lt;string&gt;"` throws a TypeError, so the drift report fails. The terraform release notes only say consumers "see `***SENSITIVE***`". They don't warn that a value's type can change from object to string.
**Fix:** Make `compareTags` skip, or report as unverifiable, any value that isn't a plain object or equals `SENSITIVE_MASK`. Add a release-note line that a wholly sensitive block becomes a string.
