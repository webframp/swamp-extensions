## Behaviour changes worth knowing

- **terraform:** `read_state` now masks every attribute marked in `sensitive_values` as `***SENSITIVE***`. This covers nested objects, lists and whole sensitive blocks. Tests cover it, and the README states the redaction. Existing stored data still holds plaintext until `read_state` runs again.
- **microsoft/teams:**
  - The bootstrap output field was already marked sensitive, so the token was already being stored in the vault, but under a generated key nobody could find. It now uses the fixed key `TEAMS_REFRESH_TOKEN` in the default vault.
  - `refreshToken` is now optional. Swamp resolves `vault.get` arguments before every run, so a missing secret blocks even `bootstrap`; I confirmed this in a scratch repo.
  - New flow: create the model with `tenantId` and `clientId` from the vault, run `bootstrap`, then add `refreshToken` with `swamp model edit`. Other methods fail with `missing_refresh_token` until it is set.
  - Two teams models in one repo would share the `TEAMS_REFRESH_TOKEN` key. The README says so.
- **exe-dev/vm:** I found an extra bug: `setup` passed a `--stdin` flag that current `swamp vault put` rejects, so storing the token always failed. The flag is removed and the token is still piped on stdin.
  - Error messages no longer echo ssh output and mask anything token-shaped.
  - `token` is now marked sensitive, so a literal token fails validation.
  - Tests cover the setup path.
- **discourse:** `apiKey` is now marked sensitive, so a literal key fails validation. A test covers it.
- **Datastores:** every example uses `"${{ vault.get(...) }}"`, including the `SWAMP_DATASTORE` forms; swamp's source shows it resolves expressions there.
  - The `connectionString` (azure-blob, postgres), `token` (gitlab) and `password` (valkey) fields are now marked sensitive. Swamp ignores this marker on datastore configs, so it is harmless.
  - The valkey `password` description now says "always" use a vault, not "prefer".
- **container-image:** the ECR password comes from a vault with a refresh hook (`--refresh-from 'aws ecr get-login-password …'`). The README offers the ECR credential helper as a password-free alternative, and GHCR/DockerHub use an interactive `vault put`.

The rest are documentation, description and error-text changes as specified (artifactory, vertex-usage, typesafe-batch, ai-usage, azure/openai-usage, dynamodb, adopt). Artifactory's false claim about automatic token rotation is gone. Vertex-usage stores credentials by piping the key file into `swamp vault put`, then deleting it, or by vaulting your ADC file.

## Decisions you should check

1. **bench needs yq and skips data migration.** `swamp datastore setup extension --config` does not resolve vault expressions; I confirmed it hands the literal expression to the provider. So `switch-datastore.sh` writes the target repo's `.swamp.yaml` datastore block with `yq` instead. The script now requires yq, and existing local data is not migrated; both are documented in the script and README. This looks like a gap in swamp worth filing upstream.
2. **bench gitlab config was broken.** The script sent `host`/`project` keys, which the gitlab-datastore config does not accept. It now sends `baseUrl`/`projectId`.
3. **bench README left unformatted.** It was not `deno fmt`-clean before my edits, so I skipped formatting it to avoid an unrelated reformat of the whole file.
4. **exe-dev default vault left alone.** The `setup` default `vaultName` is still `"gitlab"`; changing it could break users who rerun `setup` to rotate. The docs pass `--input vaultName=exe-dev --input secretKey=REDACTED explicitly. Say if you want the default changed.
