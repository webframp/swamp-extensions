### [LOW] A readable parent the token cannot administer still gets GitLab's misleading error
**File:** gitlab/extensions/models/gitlab/projects.ts **Line(s):** ~4405–4414
**Issue:** The early check only catches a parent the token cannot read. A token that can read the parent but lacks `admin_parent_link` on it (for example, Reporter on the parent's project) reaches `DestroyService#permission_to_remove_relation?`, which returns `not_found_message`. The method then throws `workItemUpdate failed: No Work Item Link found`.
**Breaking input:** A child in project A (Developer) with its parent in project B (Reporter).
**Impact:** The method still fails correctly, but the error points at a missing link rather than missing permission. This is the same confusion fix (a) addressed for unreadable parents. The README states the requirement for both ends, so this only affects diagnosis.
**Fix:** Optionally, when `errors` contains "No Work Item Link found" and `previousParent` is set, add a hint that the token needs to be able to administer both the work item and its parent.
