# README Documentation Sweep — Strategy

## Goal

Focused, low-effort documentation improvements across the 141 extension
directories in this repo: better method descriptions, usage examples, typo
fixes, and — the single biggest gap found — `## Troubleshooting` sections.
No code changes, no behavior changes.

## Survey findings

A background survey across all 141 extension READMEs found:

- **0/141 READMEs have a `## Troubleshooting` section.** This is the
  highest-leverage single gap in the repo, not specific to any one
  extension.
- **No extension is missing a README outright.** The real signal is
  thinness (line count) and terse/generic method descriptions, not
  absence.
- **~63 of 141 extensions have codegen-owned READMEs** and are **out of
  scope for hand-editing**:
  - Cloudflare (29 extensions) — `scripts/cloudflare-codegen`
  - Snyk (~20 extensions) — `scripts/snyk-codegen`
  - Datadog (14 extensions) — `scripts/datadog-codegen`

  Each codegen tool fully overwrites `README.md` (see e.g.
  `scripts/cloudflare-codegen/main.ts:248`,
  `Deno.writeTextFile(join(extDir, "README.md"), readme)`) on every
  regeneration. A hand-edited Troubleshooting section or improved method
  description in one of these READMEs would be silently lost the next
  time the codegen runs. Terse method descriptions in these families
  (e.g. `cloudflare/workers-ai`'s "Search", "List fields") come from
  preferring the OpenAPI `summary` field over the longer `description`
  field (`method_classifier.ts:150`: `op.summary || op.description || ...`)
  — a durable fix would mean changing that preference logic and the
  README template in the codegen tool itself, then regenerating all
  affected extensions. That is a separate, larger task (script change +
  ~63 regenerations + version bumps + RELEASE_NOTES for each), not part
  of this docs-only sweep. Tracked here as a candidate follow-up, not
  started.

That leaves **~78 hand-maintained extensions** as valid targets, ranked by
README thinness (excluding anything with `Auto-generated by` in its
README).

## Approach

1. **One branch, one PR** for the whole sweep (not one PR per extension —
   corrected after initially branching per-extension).
2. **Read the model/report source before writing Troubleshooting content.**
   Every Troubleshooting entry in this sweep is grounded in an actual
   `catch` block, error message, default value, or degrade path in the
   extension's TypeScript — not invented. This is what makes the sections
   worth having: they answer "why did I get an empty result / a
   confusing error" with the real mechanism, not generic advice ("check
   your credentials").
3. **Fix incorrect content found along the way.** `aws/cost-report`'s
   README documented a `swamp model report cost-est --json` command that
   doesn't exist — the correct form is
   `swamp report get <report-name> --model <model>`. Treat this class of
   bug the same as a Troubleshooting gap.
4. **Skip codegen-owned READMEs entirely** (see above) rather than
   hand-editing content that will be overwritten.
5. **No version bump / RELEASE_NOTES** for README-only changes — confirmed
   against repo precedent (`bd5c5e66`, `a43f06f9`, `c6729416`: README-only
   commits never touched `manifest.yaml`). `RELEASE_NOTES.md` is required
   only when a version bumps.

## Non-goals for this sweep

- Editing any codegen-owned README (Cloudflare/Snyk/Datadog) directly.
- Fixing the codegen tools' description-selection logic (separate task,
  noted above).
- Any change to extension code, schemas, or manifests — this sweep is
  README-only.
