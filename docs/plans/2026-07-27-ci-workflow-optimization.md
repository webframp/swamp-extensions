# CI workflow optimization

## Goal

Replace the hand-maintained CI job matrix with auto-discovery, cut the job count
roughly fourfold, and close a 55-extension coverage gap — without main ever
going red.

## Scope

`.github/workflows/ci.yml` is the primary target, with supporting changes to
`merge.yml`, `promote.yml`, `publish.yml`, `scripts/cloudflare-codegen/`, and a
new `scripts/ci-discover/`. Fourteen extensions need fixes before coverage can
expand; those carry version bumps and release notes.

Reference point for the redesign:
[umag/swamp-workspace `ci.yml`](https://github.com/umag/swamp-workspace/blob/master/.github/workflows/ci.yml).

## Current state, measured

From run `30268223013` (full CI on a six-file PR branch):

| Metric                         | Value                                |
| ------------------------------ | ------------------------------------ |
| `ci.yml`                       | 1,105 lines, 36 jobs                 |
| Jobs per run                   | 339                                  |
| Of those, the 4-task expansion | 336 (84 slots x check/lint/fmt/test) |
| Total runner time              | 3,608s (~60 min)                     |
| Mean job duration              | 8.6s                                 |
| Longest job                    | Adversarial Code Review, 538s        |
| Wall clock observed            | 8-16 min                             |
| Extensions with a manifest     | 137                                  |
| Extensions any CI job touches  | 82                                   |

A mean of 8.6s for a job that checks out the repo, installs Deno, and runs one
`deno task` means the work is almost entirely fixed setup cost. The repo is
public so runner minutes are free; the job count is what drives queue time and
what will hit platform limits.

### The coverage gap

Fifty-five extensions — 40% of the repo — are never built, linted, type-checked,
or tested. The uncovered set includes all 26 `cloudflare/*` sub-extensions, all
three `driver/*`, five `*-datastore-bootstrap`, `gitlab-review`, `threat-model`,
`discourse`, `artifactory`, `reddit`, `research-collector`, `org-simulation`,
`team-topology`, `operator-briefing`, both `hermes-*`, both `anthropic/*`, and
`extension-maintenance`.

This is not incidental. `@webframp/extension-maintenance` 2026.07.26.2 shipped
with all four methods crashing on the first call, and nothing ran its 13 tests
(fixed in #281). The `cloudflare/*` subdirectories were also the ones missing
`deno.lock` files, consistent with never having been built.

The cause is structural: every matrix list in `ci.yml` is enumerated by hand, so
an extension is covered only if someone remembered to add it. `cloudflare-test`
appears to cover cloudflare but its `working-directory` is the top-level
`cloudflare` only.

### Pre-flight results

Running all four gates locally against the 55 uncovered extensions:

| Result                | Count |
| --------------------- | ----- |
| Pass all gates today  | 41    |
| Fail `fmt` only       | 7     |
| Fail `test` only      | 4     |
| Fail `check` + `test` | 3     |

The `fmt`-only failures are mechanical. All seven `test`/`check` failures are in
`cloudflare/*`, and all of them are generated code:

```
Auto-generated by scripts/cloudflare-codegen — do not edit manually.
```

The type error traces to
`scripts/cloudflare-codegen/lib/method_classifier.ts:413`:

```ts
const argsParam = argsUsed ? "args" : "_args";
```

`argsUsed` returns false for methods whose body does reference `args`, so the
generator emits a parameter named `_args` that the body cannot see. Six errors
in `api-shield`, five in `workers-ai`, plus `stream`.

### Root cause

`scripts/cloudflare-codegen` has no CI gate. It generates 26 extensions, and
those 26 have no CI gate either. The generator already ships its own test files
— `method_classifier_test.ts`, `service_grouper_test.ts`, `type_mapper_test.ts`
— and nothing runs them. The failing logic is in a function that has a test file
sitting next to it.

Nothing under `scripts/` is checked at all: all three codegen directories are
unlinted, untyped, unformatted by CI, and missing a `fmt:check` task.

## What to take from the reference repo

**Auto-discovery instead of enumeration.**
`for m in */manifest.yaml; do dirname
"$m"; done`. Coverage becomes a property
of the filesystem rather than of someone's memory. This closes the 55-extension
gap permanently.

**Four tasks as steps in one job, not as a matrix axis.** GitHub caps a matrix
at
[256 jobs per workflow run](https://docs.github.com/en/enterprise-server@3.10/actions/using-jobs/using-a-matrix-for-your-jobs).
Auto-discovering 137 extensions with `task` as a matrix dimension is 548 jobs —
over the cap. One job per extension with four steps is 137, and pays the
checkout-plus-Deno cost once instead of four times. The current 84x4 shape
cannot scale to full coverage without this restructuring.

**Diff-scoped matrix with a fail-safe.** Classify each changed path; if anything
outside every extension directory changed, or the diff cannot be computed, run
the full matrix. The six-file PR above ran 339 checks; scoped, it would have run
one.

**`concurrency: cancel-in-progress`.** None of the four workflows has a
concurrency group today, so every superseded push runs to completion.

**The manifest-version-versus-model-version check.** Cheap, and catches a real
class of drift.

## What not to take

**Floating action versions.** The reference uses `actions/checkout@v6`,
`denoland/setup-deno@v2`, `upload-artifact@v7`. This repo pins to SHAs
(`denoland/setup-deno@667a34cdef165d8d2b2e98dde39547c9daac7282`). Keep the
pinning — it is the one dimension where the local workflow is clearly stronger.

**Its publish auth approach.** It hand-writes `~/.config/swamp/auth.json` with a
hardcoded username and collectives list. The local `publish.yml` resolves this
through a setup action and a `workflow_run` trigger gated on CI success, which
is the safer ordering.

**Skill-review, tessl, and promptfoo jobs.** Specific to that workspace's
skill-authoring concerns; no analogue here.

**Single-level discovery.** The reference globs `*/manifest.yaml`. This repo is
two deep (`aws/adopt`, `datadog/monitors`, `cloudflare/kv`). Copying it verbatim
would discover 36 extensions and silently drop 101.

## Where to improve on the reference

**Reverse-dependency expansion.** Nine extensions declare `dependencies:` on
fifteen others:

```
aws/ops              -> aws/logs, aws/metrics, aws/alarms, aws/traces,
                        aws/inventory, aws/networking
aws/cost-audit       -> aws/cost-explorer, aws/networking, aws/inventory
aws/terraform-drift  -> terraform, aws/inventory, aws/networking
aws/drift-state      -> aws/adopt, aws/inventory
ai-usage             -> aws/bedrock-usage, gcp/vertex-usage, azure/openai-usage
sre                  -> network, system
cloudflare-audit     -> cloudflare
redmine-kanban       -> redmine
agentcore-bootstrap  -> container-image, agentcore
```

`aws/inventory` has four dependents. Under naive diff-scoping, a change to it
tests only itself. The discover step must walk manifest `dependencies:` to build
a reverse edge map and expand the selected set transitively. The reference has
no answer for this.

**Discovery logic in `scripts/`, not inline YAML.** The reference embeds ~100
lines of shell in the workflow, which is untestable and exactly where the
two-level globbing bug would hide. A `scripts/ci-discover/` directory — matching
the existing per-subdirectory pattern of `cloudflare-codegen`,
`datadog-codegen`, `snyk-codegen` — can be unit-tested against committed fixture
trees.

## Decisions

1. **Main stays green at every step.** All fourteen failing extensions are fixed
   and merged before auto-discovery is enabled. No `continue-on-error` window,
   no red main.
2. **Every extension change carries a version bump and a `RELEASE_NOTES.md`
   entry**, including CI-only `deno.json` task additions. This is deliberate:
   the version stream signals to extension consumers that infrastructure is
   being maintained and the extension is live. It is not a rule misfire.
3. **Deno stays at 2.7.14.** Bumping a runtime while restructuring 339 jobs
   mixes two failure sources. Separate PR, afterwards.
4. **`.release-channel` is out of scope.** It is a `publish.yml` change,
   unrelated to matrix restructuring. Its own PR later.
5. **The task interface is already uniform enough.** 127 of 141 `deno.json`
   files have exactly `check, fmt, fmt:check, lint, test`. The bespoke inline
   shell in `ci.yml`
   (`if [ "$task" = "fmt" ]; then deno fmt --check
   extensions/vaults/ ...`)
   is a fossil from before the convention settled. Normalizing eight files
   removes the need for all of it.

Note that all eight extensions missing `fmt:check` sit inside the 55 uncovered
set. The convention held everywhere CI enforced it and nowhere else.

## Sequence

Eight PRs, each independently reviewable and revertable. Each is merged manually
after review before the next begins.

| PR | Change                                                                                                                                            | Extension bumps      | Risk        |
| -- | ------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- | ----------- |
| 1  | `Object` naming fix; `concurrency` + `cancel-in-progress` on all four workflows                                                                   | none                 | none        |
| 2  | Gate `scripts/` in CI; add `fmt:check` to 3 codegen dirs; fix `argsUsed` detection and the test-mock path bug, with generator unit tests for both | none                 | low         |
| 3  | Regenerate the affected cloudflare extensions                                                                                                     | 7, possibly up to 26 | low         |
| 4  | `deno fmt` the 7 unformatted extensions; add `fmt:check` to the 8 missing it                                                                      | ~12                  | none        |

### PR 1 — workflow hygiene

`ci.yml:203` interpolates `${{ matrix.extension }}` where the matrix entries are
objects (`{ dir: cloudflare, models: cloudflare }`), so the name stringifies to
`Object`. Eighteen jobs collapse into three names — `Object - check`,
`Object - fmt`, `Object - lint`, six apiece — so a failure cannot be attributed
to any of cloudflare/github/gitlab/system/network/twitch. Fix to
`matrix.extension.dir`.

Add to all four workflows:

```yaml
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true
```

**Verify:** job names resolve to real extension names; a second push to a test
branch cancels the first run.

### PR 2 — gate the generator, then fix it

Order matters: the generator fix must land before anything regenerates.

- New CI job running `fmt:check`, `lint`, `check`, `test` across the three
  `scripts/*-codegen` directories.
- Add the missing `fmt:check` task to each; `deno fmt` them.
- Fix `argsUsed` detection in `lib/method_classifier.ts`, with a unit test
  covering a method body that references `args` — the case currently
  misclassified.
- Diagnose and fix the test-mock path gap behind the four `test`-only failures
  (`access`, `pages`, `queues`, `turnstile`), likely in `lib/test_generator.ts`,
  with a unit test.

No extension files change, so no bumps.

**Verify:** the three existing generator test files run in CI; new tests fail
against the old logic and pass against the new.

### PR 3 — regenerate cloudflare

Blast radius to be determined before opening: regenerate locally and diff to
learn whether the generator fix changes output for all 26 cloudflare extensions
or only the 7 currently broken. If it is 26, that is 26 version bumps and
release notes — flag before proceeding rather than opening a 26-extension PR
unannounced.

**Verify:** all 26 `cloudflare/*` pass `check`/`lint`/`fmt:check`/`test`
locally; generated files still carry the do-not-edit header; no hand edits in
the diff.

### PR 4 — formatting normalization

`deno fmt` the seven unformatted extensions (`agentcore-bootstrap`,
`aurora-datastore-bootstrap`, `azure-blob-datastore-bootstrap`,
`container-image`, `driver/agentcore`, `gitlab-datastore-bootstrap`,
`hermes-journal-writer`) and add `fmt:check` to the eight missing it. Union is
about twelve extensions, each with a bump and release note.

Also document the `deno.json`-requires-a-bump rule in `CLAUDE.md` alongside the
existing test-file exception, so the reasoning is recorded rather than inferred.

**Verify:** all 55 previously-uncovered extensions pass all four gates locally.

### PR 5 — the discover script, inert

`scripts/ci-discover/` with `deno.json`, `main.ts`, `main_test.ts`, and
committed fixture trees. Emits the matrix JSON that PRs 7 and 8 will consume.
Not referenced by any workflow yet, so it can be reviewed on its own merits
rather than buried in a workflow diff.

Test cases, against real repo shapes rather than invented ones:

- two-level discovery finds both `cloudflare` and `cloudflare/kv`
- reverse-dependency expansion: touching `aws/inventory` selects
  `aws/cost-audit`, `aws/drift-state`, `aws/ops`, `aws/terraform-drift`
- transitive expansion terminates and does not loop
- a change outside every extension directory forces the full matrix
- an uncomputable diff forces the full matrix
- output is valid `fromJson` matrix input and stays under 256 entries

**Verify:** `deno task test` in `scripts/ci-discover/` passes; the new
`scripts/` CI job from PR 2 covers it automatically.

### PR 6 — collapse task-jobs

Restructure the existing hand-written matrices so each extension is one job with
four steps rather than four jobs with one step each. Coverage must stay at
exactly 82 — this PR changes shape, not scope.

**Verify:** job count drops from 339 to roughly 87; the set of extensions
exercised is unchanged; total runner time falls (expected ~48 min to ~21 min for
the extension jobs, on the reasoning that setup dominates an 8.6s mean).

### PR 7 — auto-discovery

Replace enumeration with `scripts/ci-discover`. Coverage goes 82 -> 137.

This is the step that would have failed loudly; PRs 2-4 exist so that it does
not.

**Verify:** exactly 137 extension jobs; the 55 previously-uncovered extensions
all appear and all pass; no extension is discovered twice.

### PR 8 — diff-scoping

Scope the matrix to touched extensions plus their reverse dependencies, with the
full matrix as the fail-safe. Scope the Adversarial Code Review job the same way
— at 538s it is the critical path, and it is the job whose cost scales with diff
size rather than extension count.

This is the only change in the sequence that can produce a false green, which is
why it is last and why PR 5 lands its tests first.

**Verify:** a single-extension PR runs that extension plus its dependents and
nothing else; a `.github/` change runs the full 137; a dependency-only change
runs the dependents.

## Out of scope

- Deno runtime bump from 2.7.14
- `.release-channel` per-extension publish channels
- The `audit` side-effect issue in `@webframp/extension-maintenance`
  (`getQualityScore()` invoking `swamp extension quality` per directory, which
  writes each directory's `.swamp.yaml` and creates missing `deno.lock` files);
  recorded as an `issue` verdict in that extension's adversarial review report
- CHANGELOG-based release notes; this repo uses `RELEASE_NOTES.md` per extension
- Skill-review, tessl, and promptfoo gating

## Expected outcome

A full run goes from 339 jobs at 60% coverage to roughly 137 jobs at 100%
coverage. A typical scoped PR runs single-digit job counts. `ci.yml` loses most
of its 1,105 lines, and coverage stops depending on whether anyone remembered to
edit a list.
