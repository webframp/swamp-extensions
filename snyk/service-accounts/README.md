# @webframp/snyk/service-accounts

Snyk Service Accounts — automated access management for CI/CD

Auto-generated by `scripts/snyk-codegen` from the Snyk REST API OpenAPI
specification.

## Credentials

Store the Snyk API token in a swamp vault and reference it with a `vault.get`
expression; never pass the literal value. Any vault type works —
`local_encryption`, or an extension such as `@webframp/pass`,
`@webframp/gopass`, `@webframp/hashicorp-vault` or `@webframp/macos-keychain`.

Some methods return secrets, which swamp stores in a vault (see
[Secrets](#secrets)). Because the model declares these fields sensitive, swamp
refuses to run any of its methods, reads included, until a vault exists
(`swamp vault create local_encryption snyk`).

## Usage

```bash
swamp extension pull @webframp/snyk/service-accounts

swamp vault create local_encryption snyk   # once, if you have no vault yet
swamp vault put snyk API_TOKEN             # prompts; the value never touches shell history
swamp model create @webframp/snyk/service-accounts snyk-service-accounts \
  --global-arg 'apiToken=${{ vault.get("snyk", "API_TOKEN") }}' \
  --global-arg orgId=YOUR_ORG_ID
```

## Secrets

These methods can return a secret. Swamp stores each returned value in a vault
and the persisted resource holds a `vault.get` reference in its place. Because
the model declares these fields sensitive, swamp refuses to run any of its
methods, reads included, until a vault exists
(`swamp vault create local_encryption snyk`). Snyk returns these secrets once,
on creation or rotation, so read the value from the vault.

| Method                              | Secret fields                                 |
| ----------------------------------- | --------------------------------------------- |
| `create_group_service_account`      | `access_token`, `api_key` and `client_secret` |
| `get_one_group_service_account`     | `access_token`, `api_key` and `client_secret` |
| `update_group_service_account`      | `access_token`, `api_key` and `client_secret` |
| `update_service_account_secret`     | `access_token`, `api_key` and `client_secret` |
| `create_org_service_account`        | `access_token`, `api_key` and `client_secret` |
| `get_one_org_service_account`       | `access_token`, `api_key` and `client_secret` |
| `update_org_service_account`        | `access_token`, `api_key` and `client_secret` |
| `update_org_service_account_secret` | `access_token`, `api_key` and `client_secret` |

`get_many_group_service_account` and `get_many_org_service_accounts` drop any
`access_token`, `api_key` and `client_secret` value from the listed items before
writing. Snyk returns these on creation and rotation, not in lists, and swamp
cannot vault a field inside a list.

These methods take a secret argument. Supply it with a
`${{ vault.get("<vault>", "<KEY>") }}` expression, never the literal value.

| Method                              | Secret arguments         |
| ----------------------------------- | ------------------------ |
| `update_service_account_secret`     | `data.attributes.secret` |
| `update_org_service_account_secret` | `data.attributes.secret` |

## Methods

| Method                              | Description                                             |
| ----------------------------------- | ------------------------------------------------------- |
| `get_many_group_service_account`    | Get a list of group service accounts.                   |
| `create_group_service_account`      | Create a service account for a group.                   |
| `get_one_group_service_account`     | Get a group service account.                            |
| `update_group_service_account`      | Update a group service account.                         |
| `delete_one_group_service_account`  | Delete a group service account.                         |
| `update_service_account_secret`     | Manage a group service account's client secret.         |
| `get_many_org_service_accounts`     | Get a list of organization service accounts.            |
| `create_org_service_account`        | Create a service account for an organization.           |
| `get_one_org_service_account`       | Get an organization service account.                    |
| `update_org_service_account`        | Update an organization service account.                 |
| `delete_service_account`            | Delete a service account in an organization.            |
| `update_org_service_account_secret` | Manage an organization service account's client secret. |
